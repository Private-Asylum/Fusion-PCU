# Observable six-format CPU Clamp maps

The optional CPU provider admits one checked Add/Sub/Mul/Div map in F32, F64, F16, BF16, E4M3FN or E5M2 with explicit Clamp. Public generic source remains `T: PcuCheckedFloat`; the cold constructor selects the sealed concrete clamped executor without imposing a broader consumer trait. Direct/grid/broadcast and Boundary/Strict retain the checked instruction and selected underflow law. Compound and precision permissions do not weaken this scalar arithmetic contract. PortableV1 remains unsupported for Clamp.

Two passes implement host publication without scratch allocation. Preflight records the first recovered range fault and continues validating all logical lanes. Any fatal invalid operand or zero denominator overrides recovered faults and preserves the entire caller output. A fatal-free map publishes all normal and clamped values, leaves tails untouched, then returns `Err` with `recovered=true`, the first recovered logical ID and its kind. Retry reuses the same prepared executable. Overflow publishes signed maximum finite; underflow publishes the exact destination-rounded payload, including signed zero, subnormal or a packed minimum-normal result. PCU's explicit checked fault/result contract differs from IEEE default exception-status publication. A finite/subnormal output scan cannot establish exact underflow.

Tests exercise all four operations and all three underflow policies, earlier/later recoverable/fatal permutations, mixed underflow/overflow first-fault priority, Strict borrowed scalar broadcasts, grid stride, short-input rollback, output tails and retries for all six formats. Four low-format tests independently compare 20,447,232 actual Clamp calls: all FP8 operand pairs and every half/BF16 encoding against eleven edge partners plus an affine partner, four operations and three policies. The manual binary64 decode/midpoint argument is in the sibling low-precision README; it calls no PCU arithmetic/conversion/packing. F32/F64 exact bit fixtures separately cover tiny inexact signed zero, exact subnormal rejection and tiny inexact rounding to packed minimum-normal.

Exact revision-1 host offers: F32 192–195, F64 196–199, F16 200–203, BF16 204–207, E4M3FN 208–211 and E5M2 212–215. Existing Reject IDs remain unchanged. Numerical request and IR tuples must match, including Clamp; resident boundaries and Portable receive no offer. Other CPU arithmetic, conversion and tensor profiles remain separately admitted and do not inherit Clamp from coarse capability metadata.

The source feature exercises actual generic annotated ordinary calls. The paired benchmark has six formats × four operations × N1/N4096 × prepared source/ordinary source/explicit graph/native control =192 groups. Every route alternates first-input sign, checks complete output/fault/tails on both states, verifies fatal rollback, and asserts256 warmed calls with zero allocations/reallocations/frees and unchanged cold score count. Native low-format controls use the independent midpoint oracle. Native F32/F64 controls intentionally cover only the benchmark's normal/overflow operands and fatal operand/zero checks; they do not claim general IEEE underflow classification. Semantic benchmark runs are not timing estimates.
