# Checked low-precision ordinary-source parity

Canonical Criterion target: `checked_low_precision`; ordinary generic `#[pcu]` Add/Sub/Mul/Div on F16, BF16, named OFP8 E4M3FN and E5M2. Half/BF16 use exact 2-byte unsigned storage; the named FP8 formats use exact 1-byte storage. A <=44-bit numerator / <=11-bit divisor integer implementation rounds directly to the destination encoding, without native floating arithmetic, native FP8 instructions, intermediate half/f32 rounding, FTZ, or CPU fallback.

Admission is bounded to one checked binary operation with homogeneous loads/store, direct invocation or one grid-stride loop, and optional scalar broadcast. Checked Boundary and Strict preserve each scalar operation; permitted BackendDefined compound/BackendOptimized precision requests receive the same stronger checked implementation. Full numerical requirement tuples participate in source/cache identity. PortableV1 rejects before compilation/allocation; generic low-format unary/compound expressions and general low-format tensor arithmetic remain unadmitted. Input-only owner transport retains the exact named FP8 layout, without extending inline tensor scalar payloads.

The source integration fixture compares full outputs and untouched tails with the core exact-rational oracle and a separate host binary64 midpoint-search oracle. Every finite ordered FP8 pair is covered, with fatal pairs replaced in the full-output batches and independently tested as terminal faults. Half fixtures enumerate every operand encoding once against a fixed permutation; this is not exhaustive half Cartesian coverage. All four operations and three underflow policies are tested with clamp publication. IEEE nearest/ties-even and after-rounding tininess are distinguished from PCU nonfinite rejection and execution faults. The suite checks lowest logical fault, host rollback, fatal resident discard, fresh retained ownership, preflight restoration and recovered resident publication.

Each benchmark case pairs source / explicit IR / direct native launch of the same generated kernel at full host boundaries, and source / native at resident boundaries, with two changing physical input banks. Native uses matched retained buffers/status/module/stream/geometry, including status reset after a checked fault. This is a physical same-work native baseline; independent numerical correctness comes from the oracles. Full output/tail verification is outside each timer. Resident input uploads and complete readbacks are outside timers; host input uploads and terminal output-prefix readback are inside. No warm source provider rescoring is allowed.

Sizes 65 and 65536, four formats, four operations and five peers produce 160 semantic/census rows per backend. Allocation-census builds emit no statistics; CUDA additionally asserts zero warm symbol/module/device-allocation/device-free activity and one kernel submission per caller call. ROCm Runtime `hip_call` still performs warm symbol resolution and is not certified lookup-free. Existing graph-only/manual benchmark targets remain an explicit migration backlog and are not retrospectively qualified by this canonical target.

AMD statistical samples remain refused while the user's Unreal workload is active. Correctness-only `--test` executes all peers and emits no estimates. CUDA narrow statistical evidence, exact source/binary hashes and full raw logs are recorded in the external workspace evidence directory; no universal speed or authoring-overhead claim follows from a narrow fixed-order cohort.
