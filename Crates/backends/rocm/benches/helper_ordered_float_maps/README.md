# Mutable scalar helper controls

Each genuine annotated source lane computes `stage = input + input`, reloads its own lane, then computes `output = stage * input`. The explicit IR has those same operations and both outputs. Finite changing banks have independent exact dyadic expected bits; fault probes check whole host arithmetic rollback, retry, invalid inputs, overflow, exact subnormal/tiny-inexact results, signed zero and earlier recovered status followed by a later fatal lane.

The Cartesian scope is F32/F64, N=65/4096, direct/grid, Boundary/Strict, Preserve/BackendOptimized, Checked/BackendDefined, all three underflow policies and Reject/Clamp:384 requests. Six routes yield2,304 semantic scopes and, in the separate allocation-census executable,2,304 sets of64 changing calls. Reproducibility is Unspecified. Compound permissions do not make these individually checked scalar operators unchecked.

`actual_source` and `prepared_ir` use the production safe host boundary. `native_matched_boundary` is the older extra stage upload/full readback diagnostic. `native_safe_endpoint` omits that unnecessary upload but keeps production safe endpoint CPU copies. `native_owned_minimum` directly owns input/output RAM with minimum transfers, but uses PCU-lowered code and PCU launch/completion; it is an orchestration control. These existing native lanes use the PCU-generated checked kernel. Their measured completion allocations remain visible.

`handwritten_native_owned` uses independently authored checked Add/Mul code compiled for the actual selected device through public RTC. Cold preparation obtains admitted geometry; warm calls use raw SDK launch, an explicitly retained stream and one cold retained event, with no PCU launch/completion wrapper, codegen, symbol resolution or policy reconstruction. Its bounded arithmetic/status/result probes compare with the existing checked kernel; healthy changing banks also use the independent dyadic oracle. This does not qualify unrelated operations.

The handwritten lane has five cold SDK-pinned host allocations:two changing input banks, two private N+2 result buffers and an eight-byte status word. All H2D, kernel work, status D2H and both N-element result prefixes enqueue on that same stream. One retained event proves terminal completion before CPU status interpretation or result observation. There is no default-stream dependency, warm CPU staging copy or public-slice commit copy. Fatal results remain private. Native minimum work keeps PCU's extra RAM copies visible; the matched-safe-endpoint lane remains a separate diagnostic.
