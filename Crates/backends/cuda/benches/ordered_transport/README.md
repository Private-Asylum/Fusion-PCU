# Ordered byte transport

The measured workload invokes a genuine generic `#[pcu]` function, writing stage then reloading it into output. It contains no arithmetic or numeric conversion. Source, prepared IR and minimal idiomatic native routes each upload the one input prefix, execute the same three-pointer kernel, and read both output prefixes; native omits overwritten initial output uploads and all fault-status traffic. Cold allocations retain exactly the output prefix. Caller output tails stay untouched.

The bounded cohort covers all22 sealed byte carriers, Boundary/Strict with default Checked/Preserve/IEEE/Reject, direct/grid,65/4096 elements, two changing full-byte banks and all high limbs/arbitrary float payloads. The broader policy-admission pure fixture remains separate. Each feature-gated census measures64 changing calls after warmup and reports Rust/API counters without assuming equal overhead. Source warm rescoring is rejected.

Use `--test` for untimed correctness. The whole statistical cohort requires an entry-idle device and exclusive host ownership; CUDA additionally checks foreign compute owners between phases, while AMD requires the external ownership runner. No statistical results have been qualified.

Host publication now retains private RAM per output. Every successful device read finishes before infallible copies publish either caller output; terminal arithmetic faults and SDK readback errors preserve all host outputs. Observable recovered Clamp keeps its separately specified publication+Err behavior. Both minimal and historical matched native controls stage readbacks privately too. These additional CPU copies are part of each whole host-call boundary; SDK/API counters alone do not count host memcpy bytes. Fixed-shape warm buffers are retained, and unknown completion retains the affected RAM destination alongside native allocation/runtime leases. Hardware qualification of this new implementation is separate from the frozen34c60 baseline.

The full endpoint implementation additionally stages H2D caller bytes in the native allocation's retained RAM before submission. D2H tickets retain the same allocation gate and RAM until sibling publication/drop; adapters and native controls share this endpoint rather than duplicating private buffers. The whole boundary therefore includes one H2D CPU copy and two D2H publication CPU copies for this workload. Stable shapes reuse RAM; unknown completion retains the actual allocation/RAM/runtime roots. Actual driver loss is not injected or claimed.
