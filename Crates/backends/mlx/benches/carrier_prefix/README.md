# Full-capacity resident carrier controls

This candidate has all 22 byte-aligned scalar representations × dense/grid/scalar-broadcast × N65/4096 × four routes = 528 peers. The actual workload is authored with `#[pcu]`. Captured source IR, independent hand-built IR and retained MLX native controls are paired with the ordinary annotated call after independent facade qualification.

Every measured call borrows an already retained full input of N+6 logical elements, creates one fresh private MLX output of N elements, completes it, reads the host prefix and drops the completed private owner. Ordinary calls use genuine source-produced `PcuTensor` inputs; the other peers use independent actual `MlxEncodedArray` inputs. Neither path copies the full input back to the host or changes its retained extent. Global configuration, all input uploads, exact full-shape priming and first ordinary specialization happen outside measurement. Cold preparation stages full-size synthetic inputs; its transfer and memory costs are not claimed zero.

All 64 independently varied input banks are prepared cold. Census measures 64 calls per exact dtype/profile/extent/route key and checks each output and untouched host tail after capture is disabled. It also checks that the warm invocation score callback count remains zero. Normal Criterion peers check three changed banks before and after each peer, including filtered runs. The caller allocator and scoring observer are absent unless `allocation-census` is enabled. Observed Rust allocations do not measure SDK-internal compilation, descriptor, host, device or driver allocations.

These controls remain a separate source and proof cut from the older `carrier_map` controls. That older boundary stages ordinary host inputs and records one warm caller call per census row. Compilation alone does not qualify this candidate's ordinary full-capacity path or establish any timing result.

`cargo bench -p fusion-pcu-mlx --features benchmark-control --bench carrier_prefix -- --test` runs actual Criterion semantic peers. `--features carrier-census` selects the separate untimed 64-call mode, observing caller heap/scoring plus explicit carrier adapter constructor, priming, apply and loaded-table symbol attempts. Each warm row must have 64 applies and zero new adapter constructors, primes or table lookups. These narrow counters are entirely compiled out of ordinary controls; zero adapter reconstruction is not evidence of zero SDK-internal JIT or allocation.
