# Checked wide integer tensor workload

This canonical Criterion workload executes ordinary generic `#[pcu]` owned Add/Sub/Mul, the explicitly prepared single-output graph, and an independent native launch of that graph executor's exact fixed kernel. It covers signed/unsigned128/256/512, Boundary/Strict,65/65536elements and two changing resident input banks. Independent arbitrary-precision goldens from the scalar proof check every result byte; cached sentinels check two untouched readback-tail elements without oracle heap allocation.

The physical boundary is resident inputs → fresh resident output. Each timed call allocates a fresh output and private8B checked status, initializes status, executes/waits/reads it, releases status, then releases output. Full result readback and the oracle are outside the returned workload duration, but inside the separately enabled full-call census. Native cold compilation, module/stream creation and input uploads are outside warm calls. The explicit graph uses the single-output adapter and borrowed input metadata, avoiding a gratuitous output-vector wrapper. Source-owned metadata remains part of the real authoring route.

The `allocation-census` build runs64changing-input calls per route and reports Rust heap plus SDK activity independently of Criterion statistics. It asserts no warm compilation, symbol resolution or provider rescoring. Statistical runs retain the utilization/ownership guard; `--test` executes semantic work without publishing estimates. These fixtures do not claim tensor Clamp, Portable integer arithmetic, wider floating math, or a speedup. Current device qualification is recorded separately in the GPU plans and ignored validation archive.
